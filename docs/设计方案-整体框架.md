## 1. 目标概述

ToolboxMobile 是 Toolbox（Windows 桌面端）的 Android 伴侣应用，Kotlin 编写。
整体框架包含 **3 个界面**，逻辑上分为左、中、右：

| 位置 | 界面 | 本期内容 |
|---|---|---|
| 左 | 远程连接界面 | ✅ 本期实现（固定 HTML + /24 网段 8090 端口扫描） |
| 中 | 工具界面 | ✅ 工具列表页；首个工具「DSH 远程」（WebView，2026-08-27 新增，见 §9） |
| 右 | 设置界面 | 占位页，不做具体设置 |

**分工**：AI 负责编写源码、工程配置与 CLI 构建/真机安装；Four 验收效果并决定是否 commit。

## 3. 技术选型

- 语言：**Kotlin**
- UI：**Jetpack Compose**（Material3），主框架全部自绘；**WebView 仅用于 DSH 远程工具**（§9，DSH GUI 体量大且由服务端演进，自绘不现实）
  - 三页滑动：`HorizontalPager`
  - 底栏毛玻璃：`dev.chrisbanes.haze`（Android 12+ 真模糊，低版本自动降级半透明灰）
  - WebView 深色：文档起始脚本改写 `matchMedia` 钉死 dark（§9 实测教训：algorithmic darkening 已废弃）
  - 扫码：CameraX 预览 + ML Kit barcode-scanning（模型内置，离线可用）
- 网络：OkHttp + 内存 CookieJar（等价浏览器的 `rc_session` Cookie 行为）
- 构建：Gradle Kotlin DSL，AGP 8.7.x，Gradle Wrapper 8.9
- minSdk **26** / targetSdk **35**
- 包名：`com.four.toolboxmobile`
- 权限：`INTERNET`、`ACCESS_NETWORK_STATE`、`CAMERA`（仅 DSH 扫码绑定用，运行时申请）
- cleartext HTTP：局域网面板为纯 HTTP，Manifest 设 `android:usesCleartextTraffic="true"`

**关键架构决策（2026-08-14 确认）**：连接逻辑与界面解耦——App 启动即后台扫描并维持 `/api/status` 轮询，状态存于全局 ViewModel 内存；页面切换是纯 Compose 重组，**零加载、零等待**。

## 5. 远程连接界面（左页，自绘路线）

> 2026-08-14 决策：**放弃固定 HTML + WebView 方案**，改为 Compose 自绘。
> 原因：Four 对切换顺畅度要求极高——连接状态常驻内存，切到左页必须零加载、零等待。
> WebView 方案存在首次渲染白屏、手势体系冲突、后台空转轮询等硬伤。

### 5.1 交互流程

```
App 启动（用户可能还在中间工具页）
  │
  ├─ 后台协程：扫描 /24 网段 :8090（并发 64，单连接超时 300ms，约 1s 扫完）
  ├─ 找到设备 → 用户在左页点选（或仅一台时引导点选）
  ├─ 探测 /api/status：
  │    ├─ 200 → 已连接，进入 1.2s 轮询（对齐 HTML 面板节奏）
  │    └─ 401 → 弹密钥输入卡片，POST /api/auth 成功后进入轮询
  └─ 轮询中连续 4 次失败（≈4.8s）→ 判定断开，回到错误态可重扫
```

左页 UI（Compose 自绘，toolbox 色板 1:1）：

- 顶部：`🛰️ Toolbox 远程连接` 标题 + 呼吸灯状态点（已连接绿色呼吸 / 断开红色 / 扫描中灰色）
- 扫描中：进度卡片（`x/254` + 进度条），已发现设备实时追加可点
- 设备列表：🟢 `IP:8090` 行项，点选即连；底部"重新扫描"按钮
- 密钥卡片：密码输入框（聚焦边框变绿）+ 登录按钮 + 错误提示
- 已连接：**完整控制面板**（与 HTML 面板逐卡片对齐）——快捷操作 / 文件传输（上传+共享下载）/ 电源控制（2×3 快捷网格 + 自定义分钟 + 自绘确认弹窗）/ 系统状态（CPU/内存/磁盘/电池四表，≥85% 黄 ≥95% 红，无电池浅灰满条）/ 操作日志 / 已连接设备（踢出/移除）/ 关闭 Toolbox

### 5.2 扫描逻辑（`LanScanner.kt`）

1. `NetworkInterface` 遍历取本机非回环站点本地 IPv4，推导 /24 前缀
2. 协程并发（信号量限 64）对 254 个地址 `Socket.connect(ip, 8090)`，超时 300ms
3. 进度与发现结果实时回调进 StateFlow，界面即时刷新

### 5.3 服务端协议契约（自绘端逐字节遵守，与 HTML 客户端一致）

路由表来源：`RemoteControlServer.cs` L164–182；会话：L271（`Set-Cookie: rc_session`，Max-Age 28800）；CSRF：L364 等（写操作必须带 `X-Requested-With: RemoteControl`，否则 403）。

| 接口 | 方法 | 用途 | 请求体 / 备注 |
|---|---|---|---|
| `/api/auth` | POST | 密钥登录 | `{"token": "密钥"}`，成功返回 `rc_session` Cookie |
| `/api/status` | GET | 系统状态轮询 | 响应 `data`：`cpuPercent / memoryUsedGB / memoryTotalGB / disks[] / battery{isBatteryPresent,percent,status} / uptime / ipv4` |
| `/api/command` | POST | 执行指令 | `{"command": "...", "args": {...}}` + CSRF 头；危险指令 args 恒带 `confirm:true` |
| `/api/events` | GET | 操作日志 | `data[]`：`{time, command, fromIp}` |
| `/api/devices` | GET | 设备列表 | `data.connected[]`（可踢出）+ `data.known[]`（可移除） |
| `/api/devices/kick` | POST | 踢出/移除设备 | `{"ip": "..."}` + CSRF 头 |
| `/api/transfer/upload` | POST | 上传文件到电脑 | raw body 流式 + `X-File-Name`（percent-encode，服务端 `Uri.UnescapeDataString` 解码）+ CSRF 头 |
| `/api/transfer/list` | GET | 共享文件清单 | `data[]`：`{id, name, size}` |
| `/api/transfer/download` | GET | 下载共享文件 | `?id=...`，文件名在 `Content-Disposition: filename*=UTF-8''...` |
| `/api/app/shutdown` | POST | 关闭 Toolbox | `{}` + CSRF 头 |

认证实现：OkHttp `CookieJar` 内存保存 `rc_session`，后续请求自动携带；401 时回到密钥输入态。
移动端落地：下载文件 29+ 存系统下载目录 `下载/ToolboxMobile/`，26–28 存应用私有下载目录。

## 9. DSH 远程工具（中页首个工具，WebView 路线，2026-08-27 新增）

> 需求来源：dsh-app 开启「局域网共享」后，手机浏览器凭 `http://<ip>:3081/?key=<token>` 即可远程使用 DSH。
> 本工具把这条链路搬进 App：记住密钥、自动找回入口、WebView 承载 GUI（强制深色）。

### 9.1 交互流程

```
工具页点「DSH 远程」→ 全屏覆盖层（底栏被遮盖）
  │
  ├─ 无绑定 → 绑定页：📷 扫码绑定（CameraX + ML Kit，识别 dsh-app 设置页二维码）
  │                  ⌨️ 手动输入（完整链接 / 省略协议链接 / 纯密钥）
  ├─ 有绑定 → ① 探测上次入口（一次请求，秒回）
  │           ② 不可达 → TCP 遍历 /24 网段的绑定端口（复用 LanScanner）
  │                     → 候选主机做门禁探测确认（见 §9.2）
  │           ③ 密钥不匹配 → 明确提示「重新绑定」
  └─ 定位入口 → WebView 加载 http://host:port/?key=…（门禁种 Cookie 后进 GUI）
```

- **绑定存储**：SharedPreferences `dsh`（key / host / port）；重绑覆盖旧值，换网段只更新 host
- **顶栏**：返回 / 标题 + 当前入口 host:port / 刷新 / 重新绑定
- **WebView**：JS + DOM Storage 开；双指缩放开（桌面端 GUI 适配手机）；
  **视口陷阱（2026-08-27 真机实测定案）**：代码创建的 WebView 必须显式 `MATCH_PARENT` LayoutParams——
  缺失时 WebView 按 0 高度推导视口，`vh/dvh/svh/lvh` 恒为 0（`innerHeight` 却正常），
  `html,body,#root{height:100%}` 高度链整体坍塌 → 整页白屏、只剩 fixed 弹层（内测声明弹窗残缺即此症状）；
  **深色策略**：DSH GUI 自带深色主题（`dsh-client-ui-theme`，host 无偏好时走 `system`→`prefers-color-scheme`），
  但 App 级强制夜间（DayNight + MODE_NIGHT_YES）实测**传不进 WebView 143** 的 `matchMedia`；
  最终方案 = `WebViewCompat.addDocumentStartJavaScript` 文档起始脚本改写 `window.matchMedia`，
  把 `prefers-color-scheme` 查询钉死为 dark → ThemeRuntime 解析出 dark → 原生深色（`body[data-ds-dark-theme]`，背景 #151517）。
  ⚠️ 教训：①算法反色（algorithmic darkening）会打坏 SPA 复杂组件，且 DSH 声明了 color-scheme 会自动跳过——两头不讨好，已彻底移除；
  ②给单个 WebView 套夜间上下文（createConfigurationContext）对 prefers-color-scheme 无效；
  ③WebView 跟随系统字体缩放（Edge 不跟随），已锁 `textZoom = 100`；
  ④**输入法遮挡（2026-08-27 修复）**：edge-to-edge（`setDecorFitsSystemWindows(false)`）下系统不再为
  输入法压缩窗口（adjustResize 失效），IME 高度只以 `WindowInsets.ime` 下发；整条 Compose 树无人消费
  则 WebView 保持全高、网页视口不变，聚焦输入框被键盘盖住。修复 = 内容 Column 加 `imePadding()`，
  键盘弹出时 WebView 容器变矮，Chromium 自动把聚焦输入框滚进可视区（绑定页 TextField 同受益）；
  背景预设 `#1C1C1C` 防白闪；顶部 2dp 进度条；主框架加载失败给重试入口；
  debug 包开启 `setWebContentsDebuggingEnabled`（chrome://inspect 可调试）
- **返回键**：先退 WebView 网页历史，退无可退才关闭工具
- **扫码层**：全屏覆盖（含顶栏）；半透明遮罩 + 中央镂空圆角窗 + Accent 四角框；手电开关；CAMERA 运行时权限

### 9.2 dsh-app 门禁探测协议（来源：`dsh-app/Server/LanShareProxy.cs`）

| 请求 | 密钥正确 | 密钥错误/缺失 |
|---|---|---|
| `GET /?key=<token>`（不跟随重定向） | **302**（种 `dsh_lan_key` Cookie → 跳干净地址） | 403 特征页 |
| `GET /` | — | **403** + 页面含「需要访问密钥」 |

探测判定（`probeDsh`）：
1. 带 key 请求 → 302：**再发一次无 key 请求**，403 + 特征页双确认 → `KeyOk`（排除端口上恰好是别的会 302 的服务）
2. 带 key 请求 → 403 + 特征页 → `KeyMismatch`（提示重新绑定）
3. 其余（超时/拒绝/非特征响应）→ `Miss`
